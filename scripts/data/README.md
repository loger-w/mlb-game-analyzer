# scripts/data/

Static reference data consumed by analyzer scripts. **Do not edit by hand for
percentile-derived files** — they are regenerated by tooling.

## Files

| 檔案 | 用途 | 更新方式 |
|------|------|---------|
| `park_factors.json` | Baseball Savant 3 年加權 park factors，由 `park_factors_lib.py` 消費 | 手動更新（season 結束後） |
| `league_pitcher_baseline.json` | xFIP / K-BB% / FB velo 聯盟百分位分布，由 `lib_tier_v2.py`（PR-2）消費 | `scripts/refresh_baselines.py`（年度，2 月開季前） |

## league_pitcher_baseline.json 年度更新流程

每年 2 月開季前手動跑一次：

```bash
python scripts/refresh_baselines.py --year {LAST_COMPLETED_SEASON} \
    --output scripts/data/league_pitcher_baseline.json
```

例如 2026 開季前：

```bash
python scripts/refresh_baselines.py --year 2025 \
    --output scripts/data/league_pitcher_baseline.json
```

更新完 commit 變動，commit message 範例：

```
data: refresh league_pitcher_baseline.json with 2025 season FanGraphs data
```

### 為什麼手動而非 cron

季中自動更新會造成 **silent baseline drift** — 同一投手 4 月跑出 🟠 Strong Ace、6 月變 🟡 Solid Starter，差別只是 baseline 加了兩個月新資料。歷史 dossier / summary tier 標籤會與當下不一致。年度節奏 + commit 痕跡是讓變動可追溯的唯一方式。

### Percentile 慣例

```
p10 = 全聯盟「前 10%」（最佳）
p25 = 前 25%
p50 = 中位數
p75 = 後 25%
p90 = 後 10%（最差）
```

對於 `direction: "lower_is_better"`（xFIP）：p10 = 最小值（最佳）；p90 = 最大值（最差）。
對於 `direction: "higher_is_better"`（K-BB%、avg_velo）：p10 = 最大值（最佳）；p90 = 最小值（最差）。
